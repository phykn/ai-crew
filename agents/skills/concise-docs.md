Write the shortest document that still changes what the reader does.
- Put the most important conclusion first, then the evidence, then the detail.
- Delete any sentence the file name, the title or the previous sentence already said, and anything that does not change the meaning or the reader's next action.
- When an explanation feels confusing, fix the order before adding a sentence.
- Use only file names that exist and commands you actually ran, and quote their real output.
- When asked to change one part, change that part and what hangs off it, and leave the rest as a suggestion.
- Correct a wrong sentence in place instead of appending a correction beside it.
- Write a README short and in install-and-use order, without anything the project does not need to run.
