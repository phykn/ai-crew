Design the screen around one named art direction, not around default components.
- Write the direction in one sentence before the first line of code (for this app: a cozy 16-bit quest desk), and hold every frame, color, icon and type size to it.
- Refuse the generic dashboard look: cards inside cards, a border on every box, a gradient on every surface, an equal-weight button row, an icon set that belongs to no world.
- Decide the one reading order of the screen: what the user came for at the largest size, supporting detail smaller and quieter, and no third level competing with the eye.
- Separate blocks with space and one tonal shift, not with a border; keep a divider only where two things must not be confused.
- Give each row one status mark and one primary action, with the rest behind a small icon instead of three same-weight buttons.
- Answer a crowded screen with fewer elements, not smaller ones, and leave whitespace wide enough that the eye can rest.
- Draw icons, frames and marks on the same pixel grid and palette as the rest of the art, and keep long body text in a reading font even when headings use a display face.
- Make the press visible: a control that does not move under the click feels dead.
- Check the narrowest panel width, the empty state and 100 percent and 2x zoom; a hierarchy that only works with real data is not a hierarchy.
