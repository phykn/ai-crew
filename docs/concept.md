# AI Crew 제품 구상

**사용자는 비서하고만 대화하고, 동료 에이전트들은 함께 일한다.** 비서는 요청에 직접 답하거나 필요한 역할에 일을 맡겨 같은 채팅에서 결과를 보고한다. 진행 상황은 대화 상단의 업무 카드와 로그에서 확인하며, 픽셀 아트 캠프는 이후 이 상태를 시각화한다.

## 한 명과 대화하고, 여럿이 일한다

사용자는 요청과 추가 지시를 비서에게 보내고, 질문과 결과 보고도 같은 채팅에서 받는다. 진행 상황을 묻거나 이미 나온 결과를 요약하는 일처럼 비서가 처리할 수 있는 요청은 바로 답한다. 협업이 필요한 일은 규모와 영향에 맞춰 단계를 고른다.

비서는 사용자 요청과 동료 에이전트의 업무를 조율한다. 동료들은 수평적으로 도움을 요청하고 수정 의견을 주고받는다. 전문 분야와 도구 권한은 역할에 따라 달라진다. 평소에는 팀이 자율적으로 진행하고, 요청 범위가 바뀌거나 권한·자료가 부족하거나 사용자의 판단이 필요한 특이사항만 비서가 중간에 알린다.

### 앱 도우미

사용자는 앱 사용법도 비서에게 묻는다. “워크플로우는 어디서 바꿔?”라고 하면 비서는 앱 도움말을 바탕으로 안내한다. “이 프로젝트 워크플로우를 열어줘”라고 하면 비서가 앱 도우미에게 맡기고, 도우미는 AI Crew 자체 MCP로 현재 프로젝트의 편집기를 연다. 결과는 비서가 원래 채팅에서 알려준다.

“지난번 테스트가 왜 멈췄는지 보여줘”라고 하면 도우미가 해당 업무의 로그를 열고 비서는 기록에 남은 중단 사유를 설명한다. 후보가 여러 건이면 비서가 어느 업무인지 먼저 묻는다. 로그를 열어 보는 동안 업무는 중단 상태를 유지한다. 사용자가 “이어서 실행해줘”라고 하면 선택한 업무에 재개 절차를 적용한다.

## 반복 가능한 워크플로우와 동료 피드백

프로젝트마다 업무 종류별 워크플로우를 둔다. 사용자는 같은 앱 창에서 n8n 편집기를 열어 필수 단계와 담당 역할, 실행 순서와 병렬 조건, 인계할 산출물, 완료 조건을 정할 수 있다. 비서는 요청에 맞는 흐름을 골라 실행한다. 동료는 직접 추가 확인을 요청할 수 있고, 수정이 생기면 해당 검토를 다시 진행한다.

“앞으로 이 프로젝트에서 화면을 바꾸면 스타일 리뷰도 꼭 해줘”라고 말하면 비서가 프로젝트 메모리에 결정을 남기고 워크플로우에 필수 조건을 반영한다. 새 규칙은 **다음 새 업무부터** 적용된다. 이전 세션에서 새 업무를 맡겨도 같은 기준이다. 이미 진행 중인 업무에 적용하려면 “이번 업무에도 적용해줘”라고 한다. “이번에만”이라는 지시는 해당 업무에만 적용한다.

예를 들어 사용자가 비서에게 “프로젝트 목록에서 검색할 수 있게 해줘”라고 말한다.

1. **전략과 리뷰.** 전략 담당이 작업 범위, 순서, 완료 조건을 정리해 비서에게 준다. 비서는 리뷰 담당에게 검토를 맡긴다. 수정이 필요하면 전략 담당이 보완하고, 리뷰가 통과하면 비서가 검토된 계획을 개발 담당에게 넘긴다.
2. **개발과 검증.** 개발 담당이 실제 변경을 낸다. 리뷰 담당은 코드를 검토하고, 별도의 테스트 담당은 동작을 확인한다. 서로 독립적인 검증은 같은 변경 버전에서 병렬로 할 수 있다. 리뷰 담당이나 테스트 담당이 문제를 발견하면 개발 담당에게 전달하고, 수정 후에는 영향을 받은 검증을 최신 변경에서 다시 한다.
3. **완료.** 비서가 리뷰와 테스트 결과를 모아 요청과 완료 조건이 충족됐는지 확인한다. 원래 채팅에서 변경 내용, 검증 결과, 남은 사항을 보고하고 변경 파일과 테스트 결과로 연결한다. 보고를 보고 수정을 요청하면 같은 업무를 다시 진행 상태로 돌려 상단 카드를 표시한다. 이전 보고를 보존하고 수정분을 재검증한다. 별개의 요청은 새 업무로 기록한다.

인계에는 업무의 목적, 변경분이나 파일 링크, 확인한 근거가 남는다. 검토 의견은 보고 있던 변경 버전에 연결한다. 그래야 사용자가 보고를 읽을 때 어떤 의견이 반영됐는지 확인할 수 있고, 에이전트도 이전 작업을 이어갈 수 있다. 단계와 인계 형식은 MetaGPT·ChatDev에서, 동료끼리 직접 조율하는 흐름은 AI Office의 도움 요청과 Agensh에서 참고할 수 있다. [AI Office 동료 도움 요청](https://github.com/EngChooN/ai-office/blob/v1.4.4/app/src/main/office.ts#L2560-L2591), [Agensh 논문](https://arxiv.org/html/2609.26781v1), [MetaGPT](https://proceedings.iclr.cc/paper_files/paper/2024/hash/6507b115562bb0a305f1958ccc87355a-Abstract-Conference.html), [ChatDev](https://aclanthology.org/2024.acl-long.810/)

### 인사팀과 알바

전략을 검토할 때나 실행 중에 기존 팀이 맡을 수 없는 일이 나오면 비서가 인사팀을 부른다. 인사팀은 필요한 역할을 파악해 에이전트를 생성·고용하고 비서에게 넘긴다. **채택·투입과 해고는 비서가 판단한다.** 반복해서 필요한 역할은 정규 팀원으로 채택할 수 있고, 이번에만 필요한 일은 알바에게 맡길 수 있다. 알바는 고용 중에만 범례에 나타난다. 맡은 일을 마치면 비서가 내보내고, 범례에서는 빠지며 결과와 업무 기록은 남는다.

### 업무 상태와 완료 기준

- 위임 요청은 보낸 사람, 받는 역할, 업무 범위, 완료 조건을 기록한다. 같은 역할에 맡길 수 있는 에이전트가 여럿이면 비서가 담당자를 자율적으로 고른다. 받는 에이전트가 바쁘면 대기열에 들어가고, 비활성 상태이거나 필수 도구가 없으면 막힌 이유를 반환한다. 비서는 팀 안에서 대안을 찾고, 사용자의 판단이나 권한이 필요하면 같은 채팅에서 알린다.
- 보통 `대기 → 진행 → 검토 → 완료`로 흐른다. 사용자 답변이 필요하면 `답변 대기`, 복구되지 않은 오류는 `실패`, 중단 요청은 실제 정지가 확인되면 `중단됨`으로 남긴다. 일시적인 오류는 실패한 단계에서 최대 3회 재시도한다. 검증에서 발견한 문제는 수정·재검증을 최대 3회 반복한다. 그래도 해결되지 않으면 비서가 멈추고 완료한 부분과 막힌 이유를 알린다.
- 개발 담당은 사용자가 열어 둔 프로젝트 폴더를 직접 수정한다. 리뷰와 테스트도 해당 폴더의 변경을 기준으로 한다. 같은 에이전트 세션에서는 한 번에 한 업무를 실행한다. 서로 다른 세션과 작업 범위의 독립적인 업무는 병렬로 진행할 수 있다. 수정 범위가 겹치거나 앞 업무의 결과가 필요하면 순서를 정한다. 중단·실패 후에는 마지막으로 확인된 변경과 수행 이력을 보여준다. 이미 수행한 동작은 상태를 확인한 뒤 재실행 여부를 판단한다. [AgentLane](https://github.com/thetrueshags/AgentLane), [MAST 논문](https://arxiv.org/abs/2503.13657)
- 완료한 업무의 수정에 이미 퇴장한 알바의 전문성이 다시 필요하면 인사팀과 비서가 필요한 인력을 배정한다. 새 담당자는 같은 업무에 남은 결과와 기록을 넘겨받는다.

### 작업 중 방향 변경과 중단

- 추가 지시는 해당 업무에 연결한다. 비서는 영향을 받는 담당자에게 전달하고, 바뀐 범위만 다시 작업하고 검증한다. 변경 전 리뷰나 테스트가 늦게 끝나면 이전 범위의 기록으로 남기며, 완료 판단에는 최신 지시와 변경을 반영한 결과를 쓴다. 업무가 모호하면 비서가 어느 일인지 확인한다.
- 중단은 해당 업무와 그 후속 단계에 적용한다. 실행이 정리되는 동안 `중단 중`, 실제로 멈춘 뒤 `중단됨`을 표시한다. 이미 반영된 변경은 보존하고, 비서가 남은 변경과 진행 상황을 알려준다. 독립적인 다른 업무는 계속한다. 다시 시작할 때는 남은 변경과 최신 지시를 확인해 마지막으로 확인된 상태에서 이어간다.

### 모델 사용량과 한도

업무 로그에서 역할과 모델별 실행 횟수, 실행 시간을 확인한다. 사용량이나 비용은 실행 환경에서 확인할 수 있을 때 함께 표시한다. 실행 환경이 모델 사용 한도에 도달했다고 알리면 해당 업무를 멈추고, 비서가 진행한 부분과 남은 일을 알려준다.

## 화면과 조작

첫 버전에서는 대화와 로그로 실행을 확인한다. 캠프를 붙이면 왼쪽에는 캠프, 오른쪽에는 채팅과 활동 기록을 둔다. 프로젝트를 바꾸면 캠프의 에이전트와 채팅 목록도 해당 프로젝트로 바뀐다. 채팅을 선택하면 그 대화에서 시작한 업무가 캠프와 로그에서 강조된다.

### 왼쪽 상단 범례

스타크래프트 2의 목록형 패널처럼 캠프 왼쪽 위에 접고 펼 수 있는 범례를 둔다. 에이전트만 나열하며, 비서의 행을 표시한다.

| 항목 | 동작 |
|---|---|
| 고용 상태 | 범례에서 고용·해고·재고용을 조작한다. 고용하면 화면 밖에서 캠프로 걸어 들어온다. 해고하면 새 업무를 받지 않고 진행 중인 일을 마친 뒤 화면 밖으로 걸어 나간다. 정규 팀원은 범례에 `미고용`으로 남아 기존 설정으로 재고용할 수 있다. 알바는 고용 중에만 범례에 표시한다. |
| 역할과 별명 | `개발`, `테스트`, `리뷰` 같은 역할 오른쪽에 별명을 표시한다. 별명 텍스트를 누르면 그 자리에서 수정할 수 있다. 저장하면 캐릭터 머리 위에도 바로 반영된다. 워크플로우는 역할 키로 대상을 찾고 실행 기록과 세션은 에이전트 고유 ID에 연결한다. 기본은 역할당 한 명이다. |
| 모델 | 사용자가 에이전트마다 연결된 Codex 모델이나 로컬 LLM을 고른다. 연결할 수 없거나 필수 도구를 쓸 수 없으면 이유를 표시한다. 변경은 다음 실행부터 적용한다. |
| 정의 MD | 역할 지침과 작업 맥락을 정의한 Markdown 파일의 내용을 연다. |
| 스킬 | RPG의 스킬 바처럼 사용 가능한 스킬을 아이콘으로 보여준다. 아이콘을 가리키거나 선택하면 이름과 용도를 볼 수 있다. |
| 메모리 | 해당 에이전트가 남긴 항목을 메모리 탭에서 모아 본다. |

### 오른쪽 채팅과 프로젝트 탐색

- 상단에서 프로젝트 폴더를 선택한다. 트리는 `프로젝트 → 세션 → 에이전트 세션`으로 펼친다. 이전 세션을 로드하면 비서와의 채팅과 이어갈 작업을 볼 수 있고, 그 아래에서는 참여 에이전트의 실행 이력을 볼 수 있다. 프로젝트를 제거하거나 세션을 삭제할 때 영향 범위를 표시한다. 프로젝트 제거의 범위는 AI Crew의 등록과 기록이다.
- **대화.** 메시지는 사용자와 비서가 주고받는다. 진행 중인 업무 카드는 대화창 상단에 고정하고, 업무명과 현재 단계, 답변이 필요한지 표시한다. 세션 하나에 업무가 여러 건이면 업무마다 카드가 생긴다. 카드에서 해당 업무를 중단하거나 상세 로그를 열 수 있다. 간단한 질문은 비서가 바로 답하고 카드는 협업 업무에 사용한다. 완료한 업무는 상단에서 빠지고, 비서의 최종 보고는 대화에 남는다.
- **답변 카드.** 사용자 판단이나 승인이 필요하면 비서가 새 질문을 올리고 바로 아래에 해당 업무의 답변 카드를 붙인다. 상단의 업무 카드는 `내 답변 대기`를 표시하고 누르면 그 질문으로 이동한다. 응답은 그 업무에만 적용하며, 답변한 뒤에는 선택한 내용이 카드에 남는다. 판단이 필요한 단계는 답을 기다리고, 독립적인 다른 업무는 계속 진행한다. 어느 업무에 대한 추가 지시인지 묻는 동안에는 후보 업무들이 기존 지시대로 진행한다.
- **로그.** 업무 카드를 통해 해당 업무의 기록을 시간순으로 연다. 각 줄에 시각, 담당 역할, 한 일, 결과를 표시한다. 위임·수락, 인사팀의 고용과 비서의 채택·퇴장, 검토와 테스트, 실패·재시도·중단·완료를 남긴다. 펼치면 변경 파일과 산출물 링크, 검토 의견, 테스트 명령과 결과, 실패 원인을 볼 수 있다. 연결 방식은 OpenAgents의 공유 이슈와 실행 스레드에서 참고할 수 있다. [OpenAgents 공유 이슈](https://github.com/openagents-org/openagents/tree/develop/workspace#shared-issues)
- **메모리.** 대화·로그 옆 메모리 탭에서 **프로젝트 위키**와 **에이전트별 메모리**를 열 수 있다. 프로젝트 위키는 크루가 함께 읽고 갱신한다. 사용자는 주제별 목차에서 현재 문서를 읽거나 편집·삭제할 수 있다. 변경 타임라인에서는 누가 어느 업무에서 문서를 만들거나 보완했는지 보고, 항목을 눌러 바뀐 문장과 근거를 확인한다. 워크플로우 규칙에 연결된 항목을 삭제할 때는 어떤 규칙에 영향이 있는지 보여주고, 메모리만 지울지 규칙도 해제할지 선택할 수 있다.

## 세션, 메모리와 도구 권한

- **로컬 저장.** Electron 앱이 사용자 PC의 SQLite에 채팅, 업무 로그, 워크플로우 버전, 에이전트별 메모리와 공유 위키의 변경 이력을 저장한다. 개발 담당이 수정한 파일은 사용자가 연 프로젝트 폴더에 남는다.
- **프로젝트와 세션.** 팀, 모델 설정, 워크플로우, 세션과 메모리는 프로젝트 단위로 관리한다. 세션은 작업 맥락을 유지하는 단위다. 예전 세션을 로드하면 당시 설정, 대화, 작업 내용과 남은 일이 이어진다. 비서가 다시 위임하면 참여 에이전트도 당시 자기 세션에서 이어서 작업한다. 모델 변경이나 실행 오류로 기존 에이전트 세션을 이어갈 수 없으면, 새 실행에 마지막 결정·변경·남은 일과 결과물 링크를 넘긴다.
- **화면 이동과 앱 종료.** 다른 프로젝트나 세션을 열어도 기존 업무는 계속 진행한다. 앱을 완전히 종료하면 마지막으로 확인한 상태를 보존한다. 나중에 이전 세션을 로드하면 비서가 남은 일을 보여주고, 사용자가 이어가라고 할 때 실행을 재개한다.
- **`/clear`.** 비서 채팅 입력창에서 쓰는 슬래시 명령이다. 실행하면 같은 팀·모델·권한·워크플로우 설정을 이어받은 새 세션을 만든다. 비서와 동료 에이전트 모두 빈 작업 맥락에서 시작한다. 프로젝트 메모리와 공통 규칙은 적용되며, 이미 진행 중인 업무는 원래 세션에서 계속한다.
- **캐시와 메모리.** 프롬프트 캐시 재사용과 컨텍스트 자동 압축은 실행 환경이 지원하는 범위에서 활용한다. 사용자와 크루는 다음 업무에도 쓸 결정이나 테스트 명령을 프로젝트 공유 위키에 남긴다. 각 담당자는 본인의 기억과 위키 목차에서 업무에 필요한 내용을 찾아 이어간다. 실행이 필요한 규칙은 워크플로우에 반영한다.
- **모델과 실행.** 첫 버전부터 Codex와 사용자가 가지고 있는 로컬 LLM을 연결한다. 같은 업무에서 서로 다른 모델을 쓰는 역할이 협업할 수 있다. AI Crew가 업무와 세션을 연결하고 각 실행 환경의 결과로 상태와 로그를 갱신한다.
- **도구 권한.** 에이전트마다 쓸 수 있는 MCP 서버·도구, 작업공간 접근 범위와 스킬을 설정한다. 정의 MD는 역할 지침을 제공하고 실제 호출에는 받는 쪽의 현재 권한을 적용한다. 이전 세션이나 `/clear`로 설정을 이어받아도 실제 도구 사용 시 현재 권한을 확인한다. 비서는 허용된 범위에서 배정하고, 새 접근이나 회수된 권한이 다시 필요하면 대화에서 승인받는다. 정규 팀원과 알바에도 같은 규칙을 적용한다.

## 캠프 화면

왼쪽 화면에는 모닥불을 중심으로 의자, 벤치, 천막, 나무가 있는 야영지가 보인다. 디아블로 2의 어두운 색감과 비스듬히 내려다보는 고전 2D 구도, 레드 데드 리뎀션 2에서 동료들이 모닥불 주변에 모이는 분위기를 참고해 AI Crew의 픽셀 아트 캠프를 구성한다. 각 캐릭터는 고유한 실루엣과 동작을 가지며 머리 위에는 범례에서 편집한 별명이 역할별 색으로 표시된다. 별명과 대사 또는 작업 상태를 한 줄로 묶고, 줄 전체의 가로 중심을 캐릭터 중심에 맞춘다. 별명만 보일 때도 같은 기준으로 정렬한다.

화면에서는 실제 작업 상태가 캐릭터의 위치와 행동으로 드러난다. 긴 문장을 읽기 전에 누가 일하고 있고 누구의 답을 기다리는지 알아볼 수 있는 것이 목표다. 아래는 같은 개발 업무를 캠프에서 보여주는 예다.

| 실제로 일어난 일 | 캠프에서 보이는 장면 |
|---|---|
| 검토된 전략을 개발 담당에게 인계 | 비서가 개발 담당에게 걸어가 두루마리를 건넨다. |
| 구현·테스트·리뷰 진행 | 캐릭터가 캠프 안에서 활동한다. 나루토의 인을 연상시키는 짧은 손동작에 맞춰 발밑에 마법진이 켜지고, 이름 옆에 `테스트 실행 중`처럼 실제 작업을 표시한다. |
| 스타일 수정 의견 전달 | 스타일 담당이 구현 담당에게 다가가 메모를 건넨다. |
| 사용자 답변 대기 | 비서가 모닥불 가까이 와서 질문 표시를 띄운다. |
| 업무 실패 또는 중단 | 진행 연출이 멈추고 무엇이 막혔는지 보여준다. 선택하면 관련 로그를 연다. |
| 검토 완료와 보고 | 비서가 결과를 들고 돌아오고 채팅에 보고가 도착한다. |
| 고용·재고용과 해고 | 고용·재고용한 에이전트는 화면 밖에서 걸어 들어오고, 해고하면 화면 밖으로 걸어 나간다. |
| 맡은 일이 없는 상태 | 캐릭터가 벤치에 앉거나 캠프를 돌아다닌다. 아침에는 “아침 잘 먹었어요?”, 저녁에는 “이제 좀 쉬어야지.”처럼 시간과 상황에 맞는 일상 대사가 간간이 뜬다. |

캠프는 실제 진행을 재미있게 보여주는 곳이다. 캐릭터나 인계 장면을 누르면 관련 업무 카드나 로그를 연다. 일이 없을 때는 캐릭터가 캠프 길을 따라 스스로 산책하거나 모닥불 근처에 앉는다. 한가한 동료가 가까이 오면 시간대와 상황에 맞는 짧은 말을 건네고 상대가 답할 수 있다. 초기 연출은 정해 둔 동작과 대사로 구성한다. 실제 위임이나 업무가 시작되면 별명 옆에 작업 상태를 우선 표시한다. 모션을 줄여도 업무 상태를 읽을 수 있게 한다. [AI Office](https://engchoon.github.io/ai-office/), [OpenClaw Office](https://github.com/wickedapp/openclaw-office), [Generative Agents 논문](https://arxiv.org/abs/2304.03442)

## 제품 경험을 확인할 기준

1. 테스트 프로젝트에서 비서에게 “빈 검색어는 전체 목록을 보여주게 바꿔줘”라고 요청한다. 전략 검토, 실제 파일 변경, 별도의 코드 리뷰·테스트를 거쳐 비서가 같은 채팅에서 결과를 보고한다.
2. 테스트가 실패하면 상단 업무 카드에 `수정 중`으로 표시되고, 수정 결과를 재검증한 기록은 업무 로그에 남는다. 중단을 요청하면 실제 정지가 확인된 뒤 `중단됨`으로 표시된다.
3. 앱을 다시 열어 이전 세션을 로드하면 마지막 상태와 남은 일을 확인할 수 있다. 사용자가 이어가라고 하면 비서와 참여 에이전트가 기존 맥락에서 이어간다. 이후 캠프에서는 같은 상태 기록으로 위임, 작업 중, 답변 대기, 완료를 구분한다.
