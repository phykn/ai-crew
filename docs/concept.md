# AI Crew 제품 설계

사용자는 **비서 한 명과 대화한다.** 비서가 바로 답할 수 있으면 답하고, 협업이 필요하면 크루가 업무를 나눠 처리한다. 사용자의 판단이 필요한 순간과 최종 결과는 같은 대화로 돌아온다. 프로젝트와 실행 기록은 데스크톱 앱의 로컬 SQLite에 저장한다.

## 요청 한 건의 흐름

| 단계 | 담당자와 결정 | 남기는 기록 |
|---|---|---|
| 접수 | 비서가 상태 조회, 별도 업무, 기존 업무의 추가 지시를 구분한다. 가리키는 업무가 모호하면 후보를 보여주고 묻는다. | 원래 메시지와 프로젝트·세션·업무 ID |
| 계획 | 비서가 요청의 범위와 완료 조건을 정한다. 사용자가 요청했거나 워크플로우에 사용자 검토 단계가 있을 때는 결정을 기다린다. | 계획 버전, 대상 파일·산출물, 확인 방법과 인계 |
| 개발 | 개발 담당이 현재 권한과 승인 범위에서 파일을 수정한다. 같은 파일을 쓰는 업무는 순서를 정한다. 기본 작업공간은 사용자가 연 폴더다. Git 업무는 필요할 때 별도 워크트리에서 실행할 수 있다. | 범위 예약, 승인 결정, 변경 전후 버전 |
| 검증 | 리뷰·스타일·테스트가 같은 변경 버전을 독립적으로 확인한다. 필수 검증에 실패하면 근거를 개발 담당에게 돌려준다. 일시 오류 재시도와 수정·재검증은 각각 최대 3회다. | 담당자 의견, 실행한 검사, 통과 여부와 미확인 항목 |
| 보고 | 비서가 완료 조건과 검증 근거를 대조한 뒤 결과를 같은 채팅에서 알린다. 격리 작업의 검증 완료와 원본 반영은 각각 확인한다. | 보고, 변경분과 검증 로그, 연결된 산출물 |

프로젝트마다 업무 종류별 흐름을 선택한다. 기본 개발 흐름은 비서의 계획 → 개발 → 리뷰·스타일·테스트의 병렬 검증 → 비서 보고다. 조사나 문서 업무도 같은 방식으로 역할·의존 관계·완료 조건을 정의한다. React Flow 편집기로 단계를 바꾸면 새 버전으로 저장한다. 진행 중인 업무에 적용하려면 사용자가 해당 업무를 지정한다.

[사용자 위키](https://github.com/phykn/user-wiki)의 프로젝트 지침을 관련 업무에 적용한다. Groove 흐름에 따라 비서가 검증 가능한 완료 조건을 정하고, 담당자가 작은 확인부터 수행한 뒤 근거를 인계한다. 권한 판정, 상태 전이와 복구 규칙은 [업무 실행과 복구](execution.md)를 따른다.

## 크루와 앱 도우미

- **동료 협업.** 비서는 사용자와의 소통과 배정을 조율한다. 크루끼리는 직접 도움과 검토를 요청할 수 있다. 보완 질문은 원래 요청에 연결하고, 서로를 기다리는 순환이 생기면 비서가 순서나 담당을 조정한다.
- **고용.** 인사팀이 후보를 만들고 고용을 준비한다. 채택·투입과 해고는 비서가 판단하며 사용자는 범례에서도 조작할 수 있다. 상태는 `고용`과 `미고용`이다. 정규 팀원은 설정을 유지해 재고용할 수 있고, 알바는 해고 확정과 함께 범례에서 빠진다. 업무 정리와 인계는 해당 업무에 남긴다.
- **도우미.** 앱 사용법을 물거나 조작을 부탁할 때 비서가 도우미를 부른다. 화면에서 사용자가 할 수 있는 조작은 앱 MCP에도 등록한다. 직접 클릭과 MCP 호출은 같은 검증·권한·저장 경로를 쓴다. 예를 들어 중단 이유를 물으면 로그를 열어 답하고, 재개를 요청하면 지정한 업무를 이어간다. [앱 도우미와 MCP](app-mcp.md)

## 프로젝트와 세션

- **사용자 세션**은 비서와의 대화, 초안, 맡긴 업무를 묶는다. 다른 세션이나 프로젝트를 열어도 실행 중인 업무는 원래 세션에 남는다. 앱을 다시 시작하면 저장된 상태를 읽고, 이어가라는 요청을 받으면 실행 가능 여부를 확인한다.
- **에이전트 세션**은 각 담당자의 모델 맥락을 이어가는 단위다. 기존 업무는 당시의 워크플로우 버전에서 이어간다. 새 업무는 최신 워크플로우를 사용하며 도구 호출은 현재 권한을 검사한다. 기존 모델 세션을 복구할 수 없으면 업무 체크포인트에서 새 실행으로 인계한다. 모델이 지원하는 프롬프트 캐시와 맥락 압축을 활용한다.
- **`/clear`**는 팀·모델·워크플로우 선택을 이어받은 빈 세션을 연다. 기존 업무와 대화는 원래 세션에 남는다. 새 업무에서는 공유 위키·현재 권한·최신 워크플로우 버전을 읽는다.
- **기억과 위키.** 에이전트 기억은 담당자별, 공유 위키는 프로젝트별로 관리한다. 사용자는 기억을 조회·삭제하고 위키의 문서·연결 그래프·변경 이력을 읽을 수 있다. 실행에 적용되는 규칙의 버전은 워크플로우에서 관리한다.
- **모델과 권한.** 사용자가 역할별로 Codex 또는 로컬 LLM을 고른다. 역할 정의 MD, 스킬, MCP 접근 범위를 관리하고 실제 모델·도구 지원 여부를 실행 전에 확인한다. 확인할 수 있는 실행 시간·사용량·비용은 로그에 남기고, 모델이 한도 도달을 알리면 해당 업무를 정지해 진행분을 보고한다.

## 화면에서 보이는 것

왼쪽 픽셀 아트 캠프는 위임·작업·인계·고용을 캐릭터 위치와 동작으로 보여준다. 역할색 별명과 짧은 대사는 캐릭터 중심에 맞춘다. 범례를 열면 두 가지 고용 상태, 모델·정의 MD·스킬 상태를 확인한다. 오른쪽 작업 패널의 대화, 로그, 메모리와 워크플로우는 같은 크기를 공유한다. 폴더와 승인 모드는 입력창의 보내기 줄에서, 세션은 상단 목록에서 고른다. [화면과 조작 명세](interaction.md)

## 검수 단위

실제 프로젝트를 열고 개발 업무 한 건을 맡긴 뒤 파일 변경과 세 검증을 같은 버전에서 확인한다. 같은 업무를 대상으로 승인 거절, 검증 실패, 중단과 재개도 검수한다. 완성본의 범위와 현재 확인된 동작은 [구현 계획](groove/PLAN.md)에 두며 비교 자료는 [선행 조사](research.md)에 남긴다.
