# AI Crew 핵심 기능 구현 계획

## Core

사용자는 비서하고만 대화하며, 비서는 직접 답하거나 팀의 전략·실행·검증을 조율해 같은 채팅으로 결과를 돌려준다.

## Requirements

- R1: 로컬 폴더를 프로젝트로 열고 세션을 만들 수 있다. 앱을 다시 열면 `프로젝트 → 세션 → 에이전트 세션`에서 이전 세션을 로드해 당시 대화·작업 내용·남은 일을 확인할 수 있다.
- R2: 에이전트마다 작업 맥락을 유지하는 세션이 있다. 이전 업무에 참여한 에이전트가 다시 맡으면 자기 기존 세션에서 이어서 작업한다. 사용자와 비서의 발언은 대화 탭에, 동료의 위임과 진행은 로그 탭에 표시한다.
- R3: 비서가 간단한 요청에는 바로 답한다. 협업이 필요한 개발 업무는 `전략 수립 → 전략 리뷰 → 개발 → 코드 리뷰·테스트`로 진행한다. 개발 담당은 사용자가 연 프로젝트 폴더를 직접 수정한다. 최신 변경에서 필요한 리뷰와 테스트가 통과하면 비서가 완료를 확정해 보고한다.
- R4: 역할별 지침과 도구 권한을 적용하고 UI에서 확인할 수 있다. 비서는 허용된 권한 안에서 자율적으로 배정하며, 새 접근 권한은 사용자 승인을 받는다. 신규 에이전트와 알바도 같은 규칙을 따른다.
- R5: 진행 중 추가 지시는 해당 업무의 영향 범위에 반영한다. 일시적 실패는 같은 단계에서 재시도하고, 검증 실패는 수정 후 최신 결과를 다시 검증한다. 한도에 닿으면 비서가 막힌 부분을 보고한다. 중단은 해당 업무와 후속 단계에 적용하고, 기존 변경을 보존한 채 마지막 확인 상태에서 이어갈 수 있다.
- R6: 대화창 상단에는 진행 중인 업무별 고정 카드를 둔다. 답변 카드는 비서의 질문 바로 아래에 두고, 답변 내용은 해당 업무에 연결한다. 업무별 로그에 위임·검증·실패·재시도·인사 결정과 결과물 근거가 시간순으로 남는다.
- R7: 기존 팀에 필요한 능력이 없으면 인사팀이 정규 팀원 또는 알바를 생성·고용한다. 비서는 채택·투입과 해고를 판단한다. 알바는 목적을 달성하면 결과와 업무 기록을 남기고 퇴장한다.
- R8: 첫 버전부터 사용자가 에이전트별로 Codex 또는 연결한 로컬 LLM을 고를 수 있다. 같은 업무에서 두 실행 환경의 에이전트가 협업하고, 로컬 모델의 결과도 업무 로그와 비서 보고에 반영된다.
- R9: 이전 세션을 로드하면 당시 설정과 작업 맥락을 이어간다. 채팅 입력창의 슬래시 명령 `/clear`는 팀·모델·권한·워크플로우 설정을 이어받은 빈 세션을 만든다. 프로젝트 공통 규칙과 이전 세션 이력은 계속 사용할 수 있다.
- R10: 프로젝트별로 업무 유형과 실행 조건에 맞는 워크플로우를 정한다. 비서는 다음 업무에 쓸 정보를 프로젝트 메모리에 남길 수 있다. 비서에게 요청한 지속 규칙은 워크플로우에도 반영하며, 일회성 규칙은 해당 업무에 적용한다. 사용자는 대화·로그 옆 메모리 탭에서 항목을 확인하고 삭제할 수 있다.
- R11: 범례에 에이전트만 나열하고, 역할 오른쪽의 별명을 누르면 그 자리에서 편집할 수 있다. 정규 팀원은 해고 후에도 설정과 함께 범례에 남고, 알바는 고용 중에만 보인다. 캠프는 역할별 색의 별명과 대사 또는 작업 상태를 한 줄로 묶어 캐릭터 머리 위 가로 중심에 맞춘다. 대기 중인 캐릭터는 캠프 안을 이동하거나 가까운 동료와 잡담한다.

## Design

- 데스크톱 화면: Electron과 React로 프로젝트 선택, 대화·로그·메모리 탭, 역할과 모델 설정을 제공한다. 업무별 카드에 현재 단계, 답변 대기, 상세 로그와 중단 조작을 표시한다. (R1, R2, R4, R5, R6, R8, R10)
- 로컬 저장소: SQLite에 프로젝트별 메모리, 세션 설정과 실행 환경별 에이전트 세션 참조, 업무 상태, 변경 버전, 활동 이력을 저장한다. `/clear`는 새 세션을 만들고 이전 세션 ID와 이력을 유지한다. (R1, R2, R3, R5, R6, R7, R8, R9, R10)
- 실행 연결: Electron의 Node.js 프로세스에서 Codex App Server와 기존 로컬 모델 실행 환경에 연결한다. 사용자 모델 설정을 역할별로 적용하고, 각 환경의 세션·실행 결과를 공통 업무 상태와 로그에 연결한다. (R2, R4, R5, R8)
- 워크플로우: 비서가 직접 답변과 역할 위임을 구분한다. 지시·검증 결과·답변은 개별 업무에 연결한다. 작업 범위가 겹치거나 의존하는 업무는 순서를 정하고, 프로젝트의 필수 단계와 완료 조건을 적용한다. (R2, R3, R4, R5, R6, R10)
- 인사팀: 비서가 요청한 역할과 기존 권한에 맞춰 에이전트를 준비한다. 비서의 채택·투입·해고 결정을 상태에 반영하고, 해고 후에도 설정과 이력을 보존한다. (R4, R7, R11)
- 캠프와 범례: Phaser 캠프는 배경과 캐릭터 스프라이트를 분리하고 업무 이벤트와 고용 상태를 애니메이션으로 표시한다. 대기 중에는 캠프 경로와 상황별 대사로 이동·잡담을 연출하고, 업무가 시작되면 업무 상태를 우선한다. 범례에서 고용 상태와 별명을 바꾸고, 장면을 선택하면 연결된 업무 카드나 로그를 연다. (R6, R11)

## Decisions

- T8에서 캠프 없이 첫 버전의 실제 실행을 확인한다. T9부터는 완성본에 필요한 세션·메모리·캠프 동작을 이어서 확인하는 구현 순서다. [제품 구상](../concept.md)
- Codex 연결은 App Server를 사용한다. 로컬 LLM은 사용자가 이미 가지고 있는 실행 환경의 연결 방식과 지원 기능을 확인한 뒤 연결한다. [Codex App Server](https://developers.openai.com/codex/app-server)
- 첫 워크플로우는 한 프로젝트에서 쓰기 작업 한 건으로 검증한다. 전략 리뷰와 코드 리뷰는 서로 다른 검토 단계로 기록한다. 테스트는 별도 역할이 맡는다.
- 새 세션에도 적용할 프로젝트 결정과 규칙은 프로젝트 메모리로 관리한다. 이전 작업을 이어갈 때는 해당 세션을 로드한다. 실행 환경 때문에 기존 에이전트 세션을 이어갈 수 없으면 새 실행으로 마지막 결정·변경·남은 일을 넘긴다.
- 재시도 한도는 구현 단계에서 정한다. 재실행 전에 앞선 작업의 반영 여부를 확인한다. 변경 전 지시나 파일 버전에 대한 늦은 검증 결과는 해당 업무의 이력에 남기고, 완료는 최신 지시와 변경에 대한 검증으로 판단한다.

## Tasks

- [ ] T1. 앱 뼈대와 로컬 프로젝트·채팅 저장 (R1)
  - Done when: 앱에서 폴더를 열고 세션을 만든 뒤 재실행하면 같은 프로젝트에서 그 세션을 로드할 수 있다. `README.md`에 실행 방법을 적고 실제 실행한다. `AGENTS.md`에 `docs/groove/PLAN.md` 경로와 구현을 이어갈 세션이 Groove로 첫 미완료 작업부터 진행한다는 규칙을 적는다.
- [ ] T2. 비서 채팅·세션 로드와 Codex·로컬 모델 연결 (R1, R2, R3, R4, R8)
  - Done when: 사용자가 역할별 모델을 지정한다. 비서가 진행 상황 질문에 위임 없이 답하고 앱에서 응답을 확인할 수 있다. 이전 세션을 로드하면 비서가 지난 맥락에서 답한다. 보유한 로컬 모델에 실제 입력을 보내 결과를 받는다.
- [ ] T3. 전략 검토와 개발 위임 연결 (R2, R3, R4, R6)
  - Done when: 전략 담당이 초안을 제출하고 리뷰 담당의 수정 요청을 반영한다. 검토에서 통과한 계획으로 비서가 개발 담당에게 위임하면 실제 파일이 바뀐다. 각 담당자는 자기 세션에서 작업한다. 읽기 권한만 받은 역할의 파일 수정 시도는 차단된다.
- [ ] T4. 분리된 코드 리뷰·테스트와 최종 보고 연결 (R3, R4, R6)
  - Done when: 리뷰와 별도 테스트 담당이 같은 변경을 검증한다. 수정 후에는 영향을 받은 검증을 새 버전에 수행한다. 필수 확인에 실패하면 검토 상태에 머물고, 통과하면 비서가 완료 처리하고 변경 파일·테스트·리뷰 결과를 같은 채팅에서 보고한다.
- [ ] T5. 추가 지시·재시도·중단 및 세션 재개 연결 (R1, R2, R5, R6)
  - Done when: 추가 지시는 해당 업무의 영향 범위만 바꾸고 이전 검증 결과가 새 업무 조건을 완료시키지 않는다. 일시적 실패를 재시도하고 한도에 닿으면 비서가 원인과 남은 일을 알려준다. 중단 요청 뒤 실제로 작업이 멈추면 `중단 중`에서 `중단됨`이 되고, 후속 단계가 멈춰도 독립 업무는 이어진다. 이전 세션을 로드해 재개하면 남은 변경을 확인하고 이미 반영된 변경을 중복 실행하지 않는다.
- [ ] T6. 인사팀 고용과 비서의 채택·해고 연결 (R4, R6, R7)
  - Done when: 기존 팀에 없는 역할을 요청하면 인사팀이 에이전트를 고용하고 비서가 채택한 뒤 업무에 투입한다. 정규 팀원은 이후 업무에서도 선택 가능하다. 알바는 목표를 달성하면 비서 판단으로 퇴장하고 결과와 업무 기록은 남는다.
- [ ] T7. 고정 업무 카드·답변 카드·상세 로그 연결 (R4, R5, R6, R7)
  - Done when: 한 세션에서 두 업무를 요청하면 상단에 각각의 카드가 고정된다. 새 접근 권한 요청은 비서의 질문 아래 답변 카드로 표시되고, 한 업무에 답한 내용은 그 업무에만 적용된다. 완료한 업무는 상단에서 빠지고 비서 보고는 남는다. 카드에서 업무별 로그를 열면 시각·역할·행동·결과와 변경 파일·검토 의견·테스트 명령과 결과·실패 원인을 확인할 수 있다.
- [ ] T8. 첫 버전의 정상·실패 흐름 통합 확인 (R1, R2, R3, R4, R5, R6, R7, R8)
  - Done when: `빈 검색어는 전체 목록을 보여주게 바꿔줘`를 비서에게 요청하면 사용자가 연 테스트 프로젝트의 파일이 직접 바뀐다. 전략 승인과 별도 리뷰·테스트를 확인하고, 같은 업무에서 Codex와 로컬 LLM이 맡은 결과가 로그와 최종 보고에 남는다. 테스트 실패 시 카드는 `수정 중`으로 바뀌고 최신 수정분을 재검증한다. 전문 역할을 고용한 기록을 확인하고, 중단 후 앱을 다시 열어 이전 세션에서 업무를 이어간다.
- [ ] T9. 이전 설정 로드와 `/clear` 연결 (R1, R2, R9)
  - Done when: 이전 세션을 로드하면 당시 설정과 맥락이 이어진다. 일반 대화 상태에는 상시 `/clear` 버튼을 두지 않고, 채팅에서 `/clear`를 입력해 실행하면 비서와 동료가 같은 설정을 가진 빈 세션에서 시작한다. 프로젝트 공통 규칙이 적용되고 이전 세션도 다시 로드할 수 있다.
- [ ] T10. 프로젝트 워크플로우와 메모리 탭 연결 (R9, R10)
  - Done when: 비서에게 UI 변경에 스타일 리뷰를 추가하라고 한 뒤 새 세션에서 화면 변경을 요청하면 그 단계가 실행된다. 같은 지시를 이번 일에만 적용하면 이후 업무에는 이어지지 않는다. 비서가 스스로 남긴 기억을 메모리 탭에서 출처와 시각으로 확인하고 삭제할 수 있다. 규칙이 연결된 항목은 삭제 시 영향이 표시된다.
- [ ] T11. 캠프 시각화와 범례의 고용 상태 연결 (R6, R7, R11)
  - Done when: 위임·작업은 캠프에 표시되고 장면에서 해당 업무를 열 수 있다. 대기 캐릭터가 지정 경로를 스스로 이동하고 짧은 대사가 역할별 색의 별명 옆에 뜬다. 대사 유무나 길이가 바뀌어도 줄 전체의 가로 중심이 캐릭터 중심에 맞는다. 범례에는 에이전트만 나오고, 역할 옆의 별명 텍스트를 눌러 수정하면 캐릭터 위 표시도 바뀐다. 정규 팀원은 해고 후 목록에 남아 기존 설정으로 재고용할 수 있고, 알바는 고용 때 목록에 추가되고 해고 때 목록에서 빠진다. 고용과 해고에 맞춰 캐릭터가 화면 밖에서 들어오거나 나간다.
