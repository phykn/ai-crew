# AI Crew 화면과 동작 명세

캠프에서 누가 일하는지 보고, 비서와의 대화에서 다음 행동을 정하고, 로그에서 근거를 찾는다. 역할·권한과 실행 규칙은 [제품 구상](concept.md)에, 구현 순서와 저장 구조는 [구현 계획](groove/PLAN.md)에 둔다.

## 작업 공간

| 위치 | 기본 화면 | 조작 |
|---|---|---|
| 왼쪽 캠프 | 모닥불, 캐릭터, 역할색 별명, 접힌 크루 범례 | 크루를 열어 고용과 설정을 관리한다. 일하는 캐릭터를 누르면 해당 업무의 상세 또는 승인 질문으로 이동한다. |
| 오른쪽 헤더 | 대화·로그·메모리·워크플로우 아이콘과 구분선 뒤의 세션 목록 | 포인터나 키보드 포커스로 아이콘 이름을 확인한다. 탭은 같은 패널을 쓴다. 세션 목록은 버튼 아래에서 바로 열리며 현재 프로젝트의 대화만 보여준다. |
| 대화 상단 | 진행 중인 업무마다 제목과 현재 단계 한 줄 | 제목으로 인계·상태·추가 지시·멈춤·로그를 연다. 지금 열어 둔 승인 요청은 입력창 위에 놓는다. 나머지 승인 대기는 상단에서 답할 대상을 고른다. |
| 대화 본문 | 왼쪽 비서 말풍선, 오른쪽 사용자 말풍선 | 보고에서 업무 로그를 열고, 중단 보고에서 이어간다. 시각과 화자는 메시지를 탐색할 때 확인할 수 있다. |
| 대화 하단 | 항상 같은 위치의 입력창과 폴더·승인 모드·보내기 또는 멈춤 | 폴더와 승인 모드는 버튼 위에서 바꾼다. 권한 요청은 입력창 바로 위에서 허용·거절한다. |

넓은 화면에서 캠프는 창 왼쪽 끝까지 채우고 작업 패널과 경계 한 줄을 공유한다. 좁은 화면에서는 캠프 보기와 작업 보기로 전환하며 같은 세션을 읽는다. 오른쪽 패널의 공통 폭·간격·타이포그래피는 [디자인 토큰](../demo/tokens.css)을 따른다. 화면에 보이는 제목은 현재 문서·업무·선택지를 식별하는 데 쓴다. 아이콘은 접근성 이름과 포커스 표시를 갖는다. 화면의 강조색은 현재 탭, 기본 동작과 사용자 결정에 쓴다. 역할색은 별명과 작업 연출에 쓴다. 캐릭터의 별명과 대사는 한 줄로 묶어 몸의 가로 중심 위에 배치한다.

## 요청에서 보고까지

| 상태 | 사용자가 할 수 있는 일 | 화면과 결과 |
|---|---|---|
| 새 대화·초안 | Enter 전송, Shift+Enter 줄바꿈 | 한글 조합 확정에 쓴 Enter는 전송하지 않는다. 입력창 위치는 전송 전후 동일하다. 비서가 직접 답할 수 있는 질문은 말풍선만 두 개 생긴다. |
| 협업 요청 | 업무 제목을 눌러 상세 열기 | 요청과 업무 ID를 연결한다. 단계가 바뀌면 상단 한 줄만 갱신하고 캠프는 같은 상태를 반영한다. |
| 사용자 결정 필요 | 입력창 위에서 권한 범위·요청자 확인, 허용 또는 거절 | 선택한 업무에 한 번만 적용한다. 질문은 답한 후 닫히고 결정은 로그에 남는다. 허용으로 시작하거나 거절로 종료한 결과를 표시한다. 다른 결론이 필요한 일반 질문은 해당 비서 말풍선에 표시한다. |
| 응답 생성 또는 업무 실행 | 멈춤 선택. 초안을 쓰면 보내기도 사용 | 멈춤은 버튼에 연결된 응답 또는 업무 한 건에 적용한다. 실행이 여러 건이면 대상 업무명을 입력창에서 읽는다. 업무 상세의 멈춤은 해당 업무에 적용한다. 더블클릭이나 키 자동 반복으로 뒤이어 나타난 다른 동작을 실행하지 않는다. |
| 추가 지시 | 업무 상세에서 ‘추가 지시’를 고른 뒤 작성 | 입력창에 대상이 표시된다. 다른 카드를 읽어도 초안의 수신 대상은 유지한다. 대상이 끝나면 초안을 보존하고 전송을 보류한다. 연결을 해제하거나 새 업무라고 명시하면 별도 요청으로 보낼 수 있다. “그거 다시 해줘”처럼 여러 해석이 가능하면 비서가 대상을 묻는다. |
| 멈춤·이어서 실행 | 중단 보고에서 ‘이어가기’ | 멈춤이 확인될 때까지 ‘중단 중’이다. 실제 변경과 초안은 보존한다. 이어가기는 마지막 확인 상태에서 필요한 단계만 시작한다. |
| 완료·실패 | 보고에서 해당 업무 로그 열기 | 상단에서 종료된 업무가 빠진다. 보고에는 결과·막힌 항목·미확인 범위를 남긴다. 로그에 인계와 완료 조건, 변경 버전, 검토 의견과 테스트 결과를 묶어 둔다. |

업무 대기·재시도·해고·재개는 모두 사건을 업무 ID로 기록한다. 동료가 직접 요청할 때는 요청 범위, 기대 결과, 받는 역할과 산출물을 인계하고 받는 쪽 권한으로 실행한다. 수정 범위가 겹치거나 같은 담당자가 이미 실행 중이면 뒤 업무가 기다린다. 앞 업무가 끝나면 최신 변경과 완료 조건을 확인한다. 일시 오류와 수정·재검증은 각각 최대 3회 재시도하고, 모델 한도 도달 시 진행분을 보고한 뒤 멈춘다.

읽던 대화·로그 위치와 펼친 근거를 갱신 중에도 유지한다. 최신 메시지를 읽던 경우에만 새 메시지를 따라간다. 다른 세션의 승인 요청은 세션 목록 아이콘의 건수로 알리고, 그 세션을 열었을 때 답한다.

## 반복해서 쓰는 조작

| 조작 | 결과 |
|---|---|
| 프로젝트 폴더 선택 | 보내기 줄에서 최근 폴더를 고르거나 운영체제 선택기를 연다. 취소 후 기존 입력과 초점으로 돌아온다. 같은 프로젝트를 다시 열면 마지막 세션을 불러온다. 폴더가 이동했으면 기록을 보존하고 기준 파일과 접근 권한을 확인한 뒤 재개한다. |
| 승인 모드 | 수동은 사용자, 자동은 비서, 항상은 모든 앱 권한 요청을 승인한다. 변경은 다음 권한 요청부터 적용한다. 대기 중인 질문은 그 자리에서 답한다. 새 요청·회수된 권한·알바에 모두 같은 규칙을 적용한다. |
| 세션 목록·슬래시 명령 | 첫 요청으로 대화 제목을 만들고 목록에서 제목과 최근 활동을 읽는다. 새 대화는 프로젝트 설정에서 시작한다. 이전 세션을 고르면 저장된 맥락과 초안이 이어진다. 입력창에 `/`를 쓸 때만 명령이 보이고, `/clear`를 단독으로 보내면 같은 설정의 빈 세션을 연다. 원래 업무는 원래 세션에서 계속된다. |
| 세션 삭제·프로젝트 제거 | 목록에서 삭제할 기록 범위를 확인한다. 실행 중이면 먼저 멈춘 뒤 삭제한다. 원본 폴더와 파일은 그대로 두고, 살아 있는 위키가 삭제된 세션을 참조하면 출처를 ‘삭제된 세션’으로 표시한다. |
| 로그 | 전체 기록은 사건을 시각·역할·결과로 읽는다. 업무명이나 보고의 링크로 들어오면 해당 업무만 보인다. 클릭으로 완료 조건과 근거를 펼친다. 비용 미제공은 ‘미제공’으로 표시한다. |
| 크루 범례·설정 | 역할 옆 별명을 눌러 편집한다. Enter 저장, Esc 취소. 모델·정의 MD·스킬 아이콘으로 그 담당자의 설정을 연다. 사용자가 고른 모델은 다음 실행부터 적용한다. 도구의 현재 권한은 실제 호출 직전에 확인한다. |
| 고용·해고 | 인사팀이 후보를 준비하고 비서가 채택·해고를 결정한다. 사용자는 범례에서도 조작한다. 해고로 새 배정을 닫고 하던 일의 결과나 중단 인계가 남으면 걸어서 퇴장한다. 정규 팀원은 범례에 남아 재고용할 수 있고 알바는 행이 빠진다. 후임은 이전 결과와 남은 일부터 이어받는다. |
| 메모리 | 프로젝트 위키와 에이전트 기억을 분리한다. 위키의 목록·노드는 같은 글을 열고 작성자·출처는 글 안에서 확인한다. 변경 이력에서는 작성자·시각·변경 내용을 읽는다. 담당자 기억은 각 담당자의 행에서 펼친다. |
| 메모리 편집·삭제 | 위키 저장과 변경 이력은 한 트랜잭션으로 처리한다. 충돌 시 기존 내용과 초안을 보존한다. 기억 삭제 시 관련 규칙이 있으면 기억만 지울지 규칙도 해제할지 확인하고 진행 중인 실행의 버전은 유지한다. |
| 워크플로우 | React Flow에서 위에서 아래로 읽는다. 노드 몸체를 옮기면 배치가, 연결점을 끌거나 선을 지우면 실행 순서가 바뀐다. 더블클릭 또는 Enter로 속성을 열어 이름·담당·접근·완료 조건을 편집한다. 프로젝트마다 버전과 편집 초안을 보존한다. |
| 워크플로우 저장 | 연결, 순환, 필수 합류와 완료 경로를 검사한다. 실패한 초안은 편집기 안에 남긴다. 기본은 다음 새 업무부터 적용한다. 사용자가 현재 업무에 적용할 때는 그 업무의 영향받는 단계만 재계산한다. |

## 저장·복구·접근성

- 모델이 응답하지 않으면 비서가 모델 연결 상태와 원인을 안내한다. 기존 세션을 이어갈 수 없을 때는 변경, 결정, 미완료 단계, 출처를 새 실행에 인계한다. 같은 동작이 이미 반영됐는지 확인한 뒤 재시도한다. 앱 도우미는 비서가 부르며 앱 MCP를 통해 같은 권한과 기록으로 탐색·조회·재개를 수행한다.
- 키보드로 탭·범례·업무·입력창을 탐색한다. 팝오버와 상세를 닫으면 열었던 조작으로 돌아간다. 상태·오류 문장은 해당 업무나 입력에 붙이고, 성공 표시는 저장이 확인된 뒤 갱신한다.
- 제품 인수에서는 같은 파일을 동시에 수정하는 두 업무, 중단·완료 경합, 정지 확인이 안 된 도구, 권한 회수, 한글 조합, 연결 끊김, 옛 위키·워크플로우 저장을 확인한다. 브라우저 목업은 모의 실행을 사용한다.
