# AI Crew 화면과 동작 명세

**비서에게 말하고, 캠프에서 진행을 보고, 근거가 필요할 때 기록을 연다.** 캠프는 픽셀 아트 게임처럼 읽히고, 채팅은 두 사람이 주고받은 말만 남는다. 아래 동작은 완성본의 설계 기준이다. 콘셉트 그림은 색과 분위기의 기준이며, 화면에 무엇을 표시할지는 이 문서를 따른다. [캠프 콘셉트](concept.png) · [제품 구상](concept.md)

## 1. 화면에 남기는 것

| 위치 | 기본 화면 | 필요할 때만 나타나는 것 |
|---|---|---|
| 왼쪽 캠프 | 모닥불, 고용 중인 캐릭터, 머리 위 별명, 접을 수 있는 크루 범례 | 선택한 캐릭터의 발밑 테두리, 실제 작업의 마법진, 인계 동작, 대기 중의 짧은 대사 |
| 앱 상단 | AI Crew와 워크플로우 진입점 | 한 번 누르면 현재 프로젝트의 그래프가 창 전체에 열린다. 닫으면 원래 탭·세션·초안으로 돌아온다. |
| 오른쪽 상단 | 대화·로그·메모리 탭, 오른쪽 끝에 현재 세션 제목과 ☰ | ☰는 현재 프로젝트의 대화 목록을 오른쪽 서랍으로 연다. 행에서 제목·마지막 활동·답변 대기를 읽고 한 번 눌러 전환한다. 새 대화는 서랍 안에서 만든다. |
| 대화 탭 상단 | 진행 중이거나 사용자 답이 필요한 업무가 있을 때만 고정 카드 영역 | 카드 선택 시 담당자·현재 단계·로그·멈춤. 일이 없으면 영역 전체를 접어 대화에 공간을 돌려준다. |
| 대화 본문 | 왼쪽 비서 말풍선, 오른쪽 사용자 말풍선. 같은 화자의 연속 발언은 간격을 좁힌다. | 질문에 딸린 선택지, 보고에 딸린 산출물 링크, 전송 실패한 말풍선의 재전송. 화자 이름·아바타·역할 배지·상시 시각·동료 메시지·단계별 시스템 말풍선은 생략한다. 시각은 말풍선 상세에서 확인한다. |
| 오른쪽 하단 | 여러 줄 입력창 아래 한 줄에 현재 프로젝트 폴더, 승인 모드, 오른쪽 끝 보내기 또는 멈춤을 둔다. 초안이 비어 있으면 전송은 비활성이다. | 명령 입력 중에만 명령 목록, 실행 중에는 멈춤, 실행 중 초안이 있을 때만 별도의 보내기. 모델 선택은 범례에서 한다. |

**조작 위치를 정하는 기준.** 폴더와 승인은 지금 보낼 요청의 범위와 정책이므로 입력창 안에 둔다. 대화 선택은 기록 탐색이므로 탭 옆에 둔다. 워크플로우 편집은 프로젝트의 실행 규칙을 바꾸므로 앱 상단에서 바로 연다. 폴더 목록에는 대화나 편집 버튼을 넣지 않는다. 좁은 창에서도 컨트롤의 순서를 유지하고 긴 폴더명과 세션 제목만 줄인다. 전체 이름은 포커스·목록에서 확인한다.

**정보를 펼치는 단위.** 캠프에서는 담당자의 행동, 범례 한 행에서는 역할·별명·모델·스킬을 읽는다. 별명은 직접 편집하고 모델명과 스킬 아이콘은 같은 담당자 상세를 연다. 카드는 단계·답변 대기를, 카드 상세는 담당자·완료 조건을, 로그 한 줄은 사건·근거를 보여준다. 위키는 목차와 노드 보기가 같은 문서를 연다. 그 화면에서 이미 보이는 내용을 채팅 메시지나 추가 버튼으로 반복하지 않는다.

### 항목별 노출과 도달 기준

| 사용자가 찾는 것 | 기본 상태에서 알 수 있는 정보 | 첫 조작과 다음 행동 |
|---|---|---|
| 어느 폴더에서 보낼지 | 입력창 왼쪽의 폴더 아이콘과 이름 | 버튼 바로 위에 폴더 메뉴가 열린다. 최근 폴더를 누르면 전환하고 ‘폴더 열기’에서 운영체제 선택기를 연다. 취소하면 초안과 포커스가 돌아온다. |
| 누가 권한을 승인할지 | 폴더 옆 방패와 수동·자동·항상 중 현재 값 | 누르면 세 방식의 차이와 현재 선택을 함께 읽는다. 한 번 선택하면 다음 요청부터 적용한다. 이미 접수된 질문의 허용·거절은 그 질문 안에서 처리한다. |
| 어느 대화를 보고 있는지 | 탭 오른쪽의 내용 기반 제목과 ☰ | 서랍을 열면 제목·최근 활동과 답변 대기를 비교한다. 대화 선택 또는 새 대화 후 서랍을 닫고 본문으로 돌아온다. 다른 세션에 결정이 필요할 때만 건수를 붙인다. |
| 이 일을 맡은 사람과 남은 단계 | 캠프에서는 별명·행동, 카드에서는 업무명·단계·답변 대기 | 캐릭터나 카드를 한 번 선택하면 담당자·완료 조건을 연다. ‘내 답변 대기’를 한 번 누르면 대화의 해당 질문으로 이동한다. 확인할 증거는 업무 로그에서 펼친다. 선택만으로 실행 상태가 변하지 않는다. |
| 작업 중 끼어들기와 멈춤 | 입력할 때만 보내기가 활성화되고 멈춤에는 대상 업무명이 연결된다. | Enter는 초안을 보내고 사각형은 표시한 실행만 중단한다. 새 메시지나 배경 동작은 조작 중인 버튼의 대상을 바꾸지 않는다. |
| 크루의 능력과 설정 | 범례의 역할·별명·모델·스킬, 캐릭터의 현재 활동 | 별명을 누르면 그 자리에서 편집한다. 모델명·스킬 영역에서 같은 담당자의 상세를 연다. 자세한 설정은 선택한 사람에 한정한다. |
| 누가 무엇을 기억하는지 | 메모리 탭에서 프로젝트 위키와 담당자별 기억을 구분한다. | 문서명이나 노드를 누르면 동일한 본문·근거가 열린다. 연결선은 문서 참조이며 업무 순서를 변경하지 않는다. |
| 워크플로우 흐름과 편집 결과 | 상단 진입점에서 프로젝트명·버전과 요청부터 보고까지의 그래프를 연다. | 노드 몸체는 이동, 연결점은 연결, 선택한 선은 재연결·삭제에 쓴다. 속성은 선택한 단계에만 표시한다. 오류가 있으면 캔버스와 초안을 그대로 두고 원인을 알려준다. 저장 전 닫기에는 계속 편집·버리기·저장을 제공한다. |
| 창이 좁거나 동작이 부담스러울 때 | 좁은 화면의 캠프 전환과 캠프의 모션 설정 | 화면을 전환해도 보내기와 멈춤은 같은 입력창에 있다. 모션을 줄이면 마법진·이동을 정적 상태로 표현하고 같은 상세 정보를 연다. |

**배치.** 기본 가로 비율은 캠프 3, 작업 패널 2로 시작한다. 경계선을 드래그하거나 키보드 방향키로 조정한다. 작업 패널 360 CSS px, 캠프 400 CSS px를 함께 확보하기 어려우면 한 번에 한 면을 표시한다. 좁은 창의 기본은 대화이며 ‘캠프 보기’와 ‘대화로 돌아가기’로 전환한다. 대화 탭에서는 카드와 입력창을 고정하고 말풍선 목록만 스크롤한다. 로그·메모리 탭에서는 입력창을 접고 기록을 읽는 공간을 확보한다. 대화 탭으로 돌아오면 초안을 복원한다. 고정 카드가 대화 높이의 3분의 1을 넘으면 영역 안에서 목록을 접거나 펼친다. 접힌 상태에는 선택한 업무명, 전체 건수, 답변 대기 건수만 남긴다. 별도 선택이 없으면 첫 줄에 답변 대기 업무를 우선 표시한다. 카드 영역에 들어온 새 업무는 끝에 붙이고 읽거나 포커스를 둔 행의 자리는 유지한다. 이 정렬은 멈춤 대상을 지정하지 않는다.

**시각 언어.** 짙은 숲과 천막, 모닥불빛, 캠프 장비와 어울리는 작은 아이콘을 사용한다. 채팅·로그·버튼은 확대 가능한 한글 본문 글꼴로 그린다. 역할색은 사람을, 선택 테두리는 조작 대상을 뜻한다. 질문은 물음표와 ‘내 답변 대기’, 실패는 경고 기호와 원인으로 구분한다. 마우스를 올리거나 키보드 포커스를 주면 조작 가능한 대상만 밝은 윤곽으로 표시한다. 눌렀을 때는 테두리가 안쪽으로 들어가고, 선택은 손을 뗀 뒤에도 남는 테두리로 구분한다. 활동 시간을 경험치나 진행률로 환산하지 않는다. 상태를 설명할 수 있는 단계명이 있으면 그 이름을 쓴다.

**같은 정보를 다시 보여줄 때의 기준.** 캠프는 ‘누가 움직이는지’, 카드는 ‘어느 일에 조작이 필요한지’, 로그는 ‘왜 그렇게 됐는지’를 답한다. 카드에 이미 나온 ‘테스트 중’을 비서 말풍선으로 다시 보내지 않는다. 캠프의 별명은 역할마다 달라 식별에 필요하지만 대화에서는 두 사람의 위치가 그 역할을 한다. 위키 목차에는 문서 제목, 변경 타임라인에는 작성자와 변경 내역을 놓는다. 편집기에서도 선택한 단계의 속성만 펼친다. 장식용 퀘스트 번호·등급·빈 배지·상시 도움말은 배치하지 않는다.

## 2. 채팅 입력과 멈춤

입력창의 멈춤 대상은 **현재 세션에서 화면에 표시된 응답 한 건 또는 업무 한 건**이다. 보낸 요청은 비서 응답에 연결되고, 협업으로 전환되면 같은 요청의 업무 카드가 선택된다. 다른 카드의 본문을 눌러 대상을 바꿀 수 있다. 현재 대상 이름을 멈춤 옆에 표시하고 버튼의 접근성 이름에도 포함한다. 다른 업무가 시작·종료됐다는 이유로 이미 표시된 멈춤 버튼의 대상을 바꾸지 않는다.

| 사건 또는 사용자 입력 | 적용할 동작 | 입력창과 화면의 결과 |
|---|---|---|
| 빈 입력창에 글을 쓴다 | 공백을 제외한 내용이 있으면 전송 가능. 클릭 또는 Enter로 제출하고 Shift+Enter는 줄바꿈이다. 한글 조합 중 Enter는 글자 확정에만 쓴다. | 보내기 화살표가 활성화된다. 전송 수락 후 초안이 비워지고 사용자 말풍선 하나가 생긴다. |
| 비서가 답을 생성한다 | 응답 ID에 스트림을 연결한다. 간단한 답변에는 업무를 생성하지 않는다. | 전송 자리가 ‘응답 멈춤’ 사각형으로 바뀐다. 첫 글자가 오면 비서 말풍선 하나에 이어 쓴다. 멈추면 받은 부분까지 남기며 빈 말풍선은 제거한다. |
| 비서가 업무를 위임한다 | 요청과 업무 ID를 연결한다. 응답 표시가 끝난 뒤에도 팀의 일이 남아 있으면 멈춤 대상은 그 업무다. | 상단에 업무 카드가 생기고 입력창에 ‘검색 개선 · 멈춤’처럼 대상이 보인다. 비서가 말을 마쳐도 업무 멈춤은 계속 사용할 수 있다. 위임 직전에 누른 응답 멈춤과 위임이 경합하면 원래 요청의 중단 의사를 함께 검사해 그 요청에서 새 작업이 시작된 채 방치되지 않게 한다. |
| 업무 도중 지시를 쓴다 | 멈춤은 제자리에 둔다. 초안 옆 보내기 또는 Enter로 비서에게 전달한다. 카드에서 ‘추가 지시’를 택하면 대상 업무가 입력창에 붙고 취소할 수 있다. 일반 대화에서 보낸 독립 요청은 새 업무가 될 수 있다. | 기존 업무를 멈추지 않고 내용을 전달한다. 대상이 모호하면 후보명을 질문 말풍선 아래에 붙인다. 결정까지 기존 업무는 원래 지시를 따른다. |
| 동시에 두 업무가 실행된다 | 선택한 카드의 ID에만 멈춤을 적용한다. 돌아온 세션에 선택 이력이 없고 후보가 여럿이면 버튼을 ‘멈출 업무 선택’으로 표시한다. 누르면 업무명과 단계가 열리고 항목을 선택해야 중단이 실행된다. Esc로 닫으면 모든 업무가 계속된다. 단순 답변과 백그라운드 업무가 겹치면 ‘응답 멈춤’과 각 업무 카드의 멈춤을 구분한다. | 대상을 알고 누르면 즉시 요청한다. 다른 카드, 프로젝트, 세션의 작업은 그대로 진행한다. |
| 멈춤을 누른다 | 선택 시점의 대상과 실행 ID로 중단을 한 번 요청한다. 업무는 후속 단계 배정을 닫고 활성 모델·도구 실행의 정지를 확인한다. 대기열에만 있으면 배정을 취소한다. | 즉시 ‘중단 중’으로 바뀌고 반복 누름은 무시한다. 작성 중인 초안과 반영된 파일은 보존한다. 종료 확인 후 ‘중단됨’, 입력창은 보내기로 돌아간다. |
| 멈춤과 완료가 겹치거나 연결이 끊긴다 | 저장된 종료 상태를 다시 읽는다. 이미 완료했다면 완료를 유지한다. 중단 확인이 오지 않으면 실제 실행을 조회하고, 확인 전에는 재실행하지 않는다. 취소 미지원 도구가 끝나기를 기다릴 때는 상세에 도구명과 ‘현재 실행 종료 대기’를 표시하고 후속 호출을 차단한다. | 완료 보고 또는 ‘중단 확인 중 · 상태 확인’을 보여준다. 방금 생긴 다른 업무나 새 초안이 같은 위치의 두 번째 클릭으로 실행되지 않게 한다. |
| 답변 대기·중단·실패·한도 도달 | 실행할 단계가 없으면 입력창은 보내기다. 답변 대기 업무의 카드에서 멈출 수 있다. 중단된 업무는 기존 보고나 로그의 ‘이어가기’에서 마지막 반영 상태를 확인한 뒤 재개한다. | 남은 일과 이유를 해당 업무에서 읽는다. 모델 한도 도달은 자동 재시도 횟수를 소모하지 않는다. |
| 전송에 실패하거나 수락 여부가 불분명하다 | 전송 요청 ID로 저장 여부를 확인한다. 미수락이면 같은 내용으로 재전송할 수 있고 이미 수락됐으면 기존 메시지에 연결한다. | 실패 문장 옆에만 ‘재전송’을 둔다. 입력창에 새로 쓴 글과 먼저 보낸 내용을 따로 유지한다. |

- **클릭과 키 반복.** 버튼을 누르기 시작했을 때와 뗄 때 동작·대상이 일치해야 실행한다. 전송 직후 같은 지점에 들어온 더블클릭의 두 번째 클릭과 Enter 키 자동 반복은 소비한다. 별도로 다시 누른 멈춤은 확인 창 없이 적용한다.
- **대상 변경.** 업무에 붙인 초안은 입력창 첫 줄에 업무명을 표시한다. 작성 중 다른 카드를 열면 조회 대상만 바뀌고 초안의 수신 업무는 유지된다. 입력창에서 직접 연결을 해제하거나 새 업무를 선택할 수 있다. 전송 시 이미 완료된 업무라면 같은 결과에 대한 수정인지 비서가 판별한다. 단독 명령은 화면에 열린 세션 단위로 처리한다.
- **비서가 응답할 수 없을 때.** 미고용이면 초안을 유지하고 범례의 비서 행에서 ‘재고용’, 연결 불가라면 해당 모델의 연결 상태를 열도록 안내한다. 프로젝트·로그·위키 열람과 이미 실행 중인 업무의 멈춤은 앱에서 직접 처리한다.
- **슬래시 명령.** 입력 첫머리의 단독 명령을 앱이 처리한다. 목록에서 방향키로 이동하고 Enter로 입력창에 채운 뒤 전송한다. Esc는 목록만 닫는다. 완성된 `/clear`를 직접 입력해 보내면 즉시 새 세션으로 이동한다. ‘/clear가 뭐야?’는 비서에게 가는 질문이다. 목록에서 항목을 확정한 뒤에는 목록을 닫아 다음 Enter가 제출이 되게 한다. 알 수 없는 단독 명령에는 입력값을 남기고 등록된 명령을 안내한다.
- **답변 카드.** 질문 바로 아래 말풍선에 붙여 한 덩어리로 읽히게 한다. 권한 승인은 대상 역할·도구·범위를 보여준 뒤 허용 또는 거절할 수 있다. 선택 또는 직접 작성한 답을 질문 ID에 한 번만 연결한다. 첫 유효 응답 뒤에는 선택 결과만 남긴다. 중단됐거나 새 질문으로 대체됐으면 기존 선택지를 닫는다.
- **읽던 위치.** 최신 메시지를 보고 있을 때만 스트리밍을 따라간다. 위로 스크롤한 사용자는 그 자리에 두고 ‘새 메시지’로 최신 위치에 이동하게 한다. 다른 탭에서 돌아올 때 초안, 스크롤, 선택한 업무를 세션별로 복원한다. 업무 완료와 캠프 대사가 입력 포커스를 가져가지 않는다.

## 3. 캠프, 범례와 인사

| 조작·사건 | 업무 규칙 | 화면 반응과 예외 |
|---|---|---|
| 캐릭터 선택 / 빈 땅 클릭 | 캐릭터 선택은 조회다. 한 업무면 그 카드나 로그, 여러 건이면 업무명 선택, 대기 중이면 범례의 해당 행을 연다. 빈 땅은 선택 해제다. | 발밑에 선택 테두리를 표시한다. 작업 마법진은 실제 실행 중에만 켜진다. 배경을 눌러도 이동·배정 명령은 발행되지 않는다. |
| 업무 요청·인계 / 대기 | 저장된 요청 이벤트가 발생하면 보낸 사람이 받는 사람 쪽으로 접근한다. 이미 다음 단계가 시작됐다면 최신 상태를 먼저 그린다. | 두 사람 머리 위에 요청·수신 상태가 나타난다. 작업이 시작되면 잡담을 즉시 접는다. 별명과 한 줄 대사의 묶음을 몸 중앙에 정렬하고 겹치면 잡담부터 숨긴다. |
| 범례 접기 / 행 열기 | 접힘은 화면 설정이다. 행에는 고용 상태, 역할, 별명, 모델, 정의 MD, 스킬을 둔다. 좁을 때는 역할·별명을 우선하고 도구와 메모리는 행 상세에서 연다. | 접힌 헤더에 ‘크루’와 고용 인원만 남긴다. 모델 로딩이나 긴 스킬 목록 때문에 채팅 폭이 변하지 않는다. |
| 별명 선택·편집 | 텍스트 클릭 또는 키보드로 편집한다. Enter는 저장, Esc는 취소, 포커스 이탈은 유효한 값만 저장한다. 빈 값은 이전 값으로 되돌린다. | 저장 후 범례·캐릭터 이름이 함께 바뀐다. 동명이인은 역할과 선택한 행으로 구별하고 실행은 고유 ID에 연결한다. 별도 연필 버튼은 생략한다. |
| 모델 선택 | 사용자만 담당 모델을 바꾼다. 연결·필수 기능을 확인하고 저장한다. 진행 중인 단계는 시작할 때의 모델, 다음 실행은 새 모델을 쓴다. | 선택란에 현재 설정을 표시한다. 적용 대기 중이면 상세에 ‘다음 실행부터’를 표시한다. 연결 실패 시 기존 선택과 초안을 유지하고 이유를 보여준다. |
| MD·스킬·메모리 열기 | MD는 역할 지침을 연다. 스킬 아이콘은 이름·용도·필요 도구를 표시한다. 메모리는 같은 프로젝트에서 해당 담당자로 필터링한다. | 키보드 포커스로도 상세를 읽을 수 있다. 팝오버를 닫으면 열었던 행으로 돌아간다. |
| 고용 / 재고용 | 역할이 부족하면 인사팀이 후보를 준비하고 비서가 채택·투입한다. 범례에서 사용자가 고용하는 경우에도 같은 고용 상태를 기록한다. | 채택한 팀원이 들어온다. 정규 팀원 재고용은 기존 행과 설정을 사용한다. 알바는 고용 중에만 별도 행이 생긴다. |
| 해고 | 새 배정을 닫고 대기 요청을 재배정한다. 진행 중이면 현재 단계의 결과나 중단 인계를 기록한 뒤 퇴장한다. 비서가 내보내는 경우에도 동일하다. | 정리 중에는 ‘퇴장 예정’, 정규 팀원은 퇴장 후 ‘재고용’, 알바는 행 제거. 옛 로그에서 작성자와 산출물은 계속 열린다. |
| 모션 줄이기 | 시스템 설정을 따르며 앱에서 바꿀 수 있다. 실행과 인사 처리는 저장된 이벤트로 확정한다. | 이동·손동작·불꽃 점멸을 정적 포즈·고정 문구로 바꾼다. 걸어가는 도중 전환해도 인계 로그는 한 건이고 같은 업무를 선택할 수 있다. |

## 4. 업무 카드, 로그와 실행 규칙

상단 카드는 ‘검색 개선 · 테스트 중’처럼 **업무명과 현재 단계**만으로도 읽혀야 한다. 단계 상세·증거·사용량은 로그를 열었을 때 제공한다. 완료 시 고정 영역에서 빠지고 최종 보고가 대화에 남는다. 실패·중단으로 실행이 끝난 업무도 로그와 비서 보고에서 찾을 수 있다.

| 조작·사건 | 바뀌는 상태 | 화면에 남는 근거 |
|---|---|---|
| 업무 카드 선택 / 답변 대기 표시 선택 | 일반 선택은 작업 대상을 강조한다. 답변 대기 표시는 연결된 질문으로 이동한다. | 입력창 대상·관련 캐릭터를 강조한다. 질문 이동으로 승인되거나 실행이 재개되는 일은 없다. |
| 비서가 업무를 받음 | 단순 질문은 직접 응답한다. 협업은 업무 ID, 지시 버전, 워크플로우 버전과 완료 조건을 저장하고 적격 담당자를 배정한다. | 협업에만 카드가 생긴다. 단계 전환은 같은 카드를 갱신하고 새 말풍선을 쌓지 않는다. |
| 담당자가 동료에게 요청 | 범위·기대 결과·받을 역할을 기록한다. 바쁘면 대기, 같은 요청의 보완 질문은 기존 요청에 연결한다. 받는 쪽 권한으로 작업한다. | 캠프에 인계 장면, 로그에 요청과 응답 한 쌍이 남는다. 새 권한이나 사용자 판단이 필요할 때 비서가 질문한다. |
| 수정 범위가 겹침 | 파일·상하위 경로·의존성을 확인해 뒤 작업을 대기시킨다. 앞 작업 종료 후 최신 파일과 기준을 다시 읽고 진행한다. | 카드에는 ‘앞 업무 대기’, 상세에는 선행 업무와 파일이 보인다. 기다리는 캐릭터에 작업 마법진을 표시하지 않는다. |
| 리뷰·스타일·테스트 결과 도착 | 지시·변경 버전에 결과를 묶는다. 기본 개발 업무는 세 갈래 검증이 같은 변경 버전을 확인하고, 현재 버전의 필수 결과가 갖춰져야 비서가 완료를 확정한다. | 파일, 검토 의견, 명령·결과를 펼쳐 읽는다. 이전 버전 결과는 이력으로 표시한다. |
| 오류·검증 실패 / 모델 한도 | 일시 오류는 최초 시도 뒤 최대 3회 재시도한다. 검증 실패는 수정·재검증 최대 3회다. 한도 도달은 해당 업무를 멈추고 비서가 남은 일을 보고한다. | 진행 중에는 ‘재시도 1/3’ 또는 ‘수정 중’. 해결되지 않으면 원인·확인된 변경·남은 일과 로그를 보고한다. |
| 비서 보고 뒤 수정 요청 | 같은 결과를 고치면 기존 업무를 다시 활성화한다. 퇴장한 알바의 일은 기록과 권한을 확인해 후임이 이어받는다. 별개 요청이면 새 업무를 만든다. | 같은 업무 카드가 돌아오고 이전 보고는 남는다. 최신 변경에 영향을 받는 단계만 재검증한다. |
| 로그·변경 파일·사용량 열기 | 선택한 업무 범위에서 시각·역할·행동·결과를 읽는다. 항목을 펼치면 변경 버전과 당시 근거를 읽는다. | 조회만으로 업무가 재개되지 않는다. 없는 파일은 경로와 기록된 변경을 표시한다. 공급자가 비용을 주지 않으면 ‘미제공’으로 구분한다. |

## 5. 프로젝트와 세션

| 조작·조건 | 저장·실행 결과 | 화면과 복구 |
|---|---|---|
| 승인 모드 변경 | 프로젝트별로 수동·자동(비서 판단)·항상(모든 앱 권한 승인) 중 하나를 저장한다. 변경 뒤 접수된 권한 요청부터 적용하고 대기 중인 질문은 기존 결정을 기다린다. | 보내기 줄에 현재 모드를 표시하고, 로그에서 누가 어떤 범위를 무슨 이유로 승인·거절했는지 확인한다. 기본은 수동이다. |
| 첫 실행 / 폴더 선택 | 등록된 프로젝트가 없으면 ‘프로젝트 폴더 열기’를 제공한다. 이미 등록한 폴더는 기존 프로젝트를 선택한다. 폴더 선택 취소는 현재 상태를 유지한다. | 선택 뒤 세션 목록, 빈 세션에서는 입력창을 바로 쓸 수 있다. 예시 채팅이나 가짜 진행 카드는 생성하지 않는다. |
| 트리 펼치기 / 다른 세션 선택 | 폴더 선택기는 프로젝트를 고르고, ☰ 서랍은 그 프로젝트의 세션을 나열한다. 상세 기록의 소속 관계는 프로젝트 → 세션 → 참여 에이전트 세션이다. 프로젝트·세션 선택은 조회 범위를 바꾼다. 에이전트 세션을 누르면 실행 기록을 연다. | 해당 캠프와 채팅이 함께 바뀐다. 전환 전 초안과 실행은 원 세션에 남는다. 담당자와 별도 대화창을 열지 않는다. |
| 이전 세션 / 새 세션 / `/clear` | 이전 세션은 비서와 각 담당자의 맥락을 이어간다. 새 세션은 프로젝트 기본 설정으로 시작한다. `/clear`는 현재 팀·모델·권한 설정과 워크플로우 선택을 계승한 빈 맥락으로 시작한다. 새 업무에는 최신 프로젝트 규칙·현재 권한을 적용한다. | 세션 선택기가 새 대상을 표시한다. 원래 업무는 원래 세션에서 계속되고, 새 세션에서도 프로젝트 위키를 열 수 있다. |
| 앱 재시작 / 로컬 모델 세션 만료 | 마지막 확인 상태를 불러온다. 사용자 재개 지시 후 기존 실행 상태부터 확인하며 재개 불가 때는 결정·변경·남은 일·출처를 새 모델 실행에 인계한다. | 기존 카드와 로그를 유지한다. 이미 적용됐을 수 있는 변경의 결과를 모르면 비서가 확인을 요청한다. |
| 세션 삭제 / 프로젝트 제거 | 메뉴에서 대상과 삭제될 앱 기록 범위를 먼저 보여준다. 실행 중인 업무가 있으면 해당 업무로 이동해 멈추거나 삭제를 취소할 수 있다. 정지 확인 후 명시적으로 삭제한다. | 세션 삭제는 해당 세션 소속 기록에, 프로젝트 제거는 해당 프로젝트의 앱 기록에 적용한다. 원본 폴더·파일을 유지한다. 남은 위키가 삭제된 세션을 인용하면 출처를 ‘삭제된 세션’으로 표시한다. 선택 중인 세션이 삭제되면 그 프로젝트의 세션 목록, 프로젝트가 제거되면 프로젝트 선택 화면으로 돌아간다. |
| 폴더가 이동되었거나 접근을 잃음 | 프로젝트 기록은 남겨 두고 파일 접근이 필요한 실행을 보류한다. 사용자가 같은 프로젝트의 폴더를 다시 지정하면 기준 경로와 마지막 변경을 확인한다. | 선택기에 원래 경로와 ‘폴더 다시 선택’을 제공한다. 권한과 기준 파일을 확인한 뒤 해당 업무에서 재개한다. |

## 6. 위키, 편집기와 도구 권한

| 조작 | 업무 규칙 | 반응·실패 처리 |
|---|---|---|
| 위키 노드 선택 | 현재 프로젝트의 위키 문서가 노드이고 명시적 참조가 연결선이다. | 노드를 누르면 목록에서 고른 것과 같은 문서의 본문·출처를 연다. 참조가 없는 문서도 표시한다. |
| 위키 목차 / 변경 타임라인 선택 | 목차는 최신 본문, 타임라인은 선택한 버전의 작성자·시각·변경 문장·출처를 조회한다. | 같은 탭에서 본문과 근거를 왕복한다. 빈 위키는 첫 문서를 작성하는 동작만 제공한다. |
| 사용자 또는 에이전트가 위키 저장 | 프로젝트, 문서, 기준 버전을 확인해 본문과 이력을 함께 기록한다. 다른 작성자가 먼저 저장했으면 양쪽 내용을 보존하고 최신본과 초안을 다시 비교해 저장한다. | 문서는 하나, 작성 이력은 변경마다 한 건이다. 저장 실패 시 입력한 문장을 보존한다. |
| 담당자 기억 보기 / 지우기 | 에이전트별 기억은 프로젝트와 담당자 ID로 찾는다. 삭제한 기억은 이후 메모리 입력에서 제외한다. | 범례에서 들어오면 해당 담당자 필터가 적용된다. 원래 대화와 업무 로그는 출처로 남는다. |
| 위키 문서·기억 삭제 | 삭제는 항목 메뉴에서 시작한다. 연결된 규칙이 있으면 이름과 영향을 표시하고 ‘기억만 삭제’ 또는 ‘규칙도 해제’를 선택한다. 해제는 새 규칙 버전으로 저장한다. | 목차·메모리 입력에서 제거한다. 진행 중인 업무는 시작한 규칙 버전을 유지한다. 삭제 취소 시 선택한 항목으로 돌아간다. |
| 워크플로우 열기 / 노드 선택·이동 | 단계를 누르면 옆에 담당 역할·권한·완료 조건이 펼쳐진다. 노드 몸체 드래그는 배치, 오른쪽 연결점에서 다음 노드 왼쪽 연결점으로 드래그는 선행 조건 추가다. 선 끝점을 끌어 대상을 바꾸거나 선 선택 후 삭제한다. 드래그는 화면 배치 초안만 바꾼다. 단계 추가·삭제와 연결선 편집은 실행 규칙 초안을 바꾼다. | 편집기는 같은 창에서 열리고 현재 세션을 기억한다. 단계 삭제 시 연결선도 함께 초안에서 제거한다. 역할을 고르면 현재 사용 가능한 담당자를 확인할 수 있다. 연결선 오류는 해당 노드 옆에 원인과 수정 지점을 표시한다. |
| 워크플로우 저장 / 닫기 | 참조·순환·필수 합류·완료 경로를 검사하고 유효한 버전만 저장한다. 저장 시 기준 버전이 바뀌었으면 사용자의 초안을 보존한다. 수정 중 닫으면 저장·버리기·계속 편집을 선택한다. | 저장 결과에 ‘다음 새 업무부터’를 표시한다. ‘이번 업무에도’는 지정 업무만 다시 계산하고 ‘이번에만’은 프로젝트 기본 규칙을 유지한다. |
| 스킬 추가·해제 / MCP 부여·회수 | 범례 상세에서 담당자·도구·접근 범위를 선택한다. 실행 직전에 현재 권한을 확인한다. 이미 접수된 대기 호출도 회수된 권한으로 실행할 수 없다. | 등록된 스킬과 실제 도구 권한을 따로 표시한다. 비서의 승인 질문에 거절하면 해당 경로를 닫고 허용된 대안을 찾거나 막힌 이유를 보고한다. |
| 앱 도우미 호출 | 사용법은 도움말, 업무 상태는 앱 MCP의 기록을 읽는다. ‘열어줘’는 탐색, ‘이어서 실행해줘’는 명시한 업무에 재개 규칙을 적용한다. | 비서가 같은 대화에서 결과를 알려준다. 권한·프로젝트 범위 오류는 요청한 동작에서만 표시한다. |

## 7. 접근성, 주의와 오류

- **키보드.** 오른쪽 패널의 키보드 이동 순서는 대화·로그·메모리 탭, 세션 목록, 선택한 탭의 본문 순이다. 대화 탭에서는 입력창 다음에 폴더·승인·보내기 또는 멈춤이 이어진다. 범례·캐릭터의 기능은 키보드로 조작 가능한 범례 행과 카드에서도 제공한다. React Flow의 역할과 선행 단계는 선택한 노드 상세에서 키보드로 변경할 수 있다. 닫은 메뉴·대화상자는 열었던 컨트롤에 포커스를 돌려준다.
- **포커스와 판독.** 아이콘은 기능과 대상이 담긴 접근성 이름을 갖는다. 채팅의 화자는 화면 낭독기에서만 읽는다. 스트리밍은 단어마다 읽지 않고 의미 있는 응답 단위로 알린다. 입력창에서 빈 Enter와 Esc는 업무를 멈추지 않는다. 키보드로 멈추려면 해당 버튼에 포커스를 두고 활성화한다.
- **가독성.** 본문 일반 텍스트는 배경과 4.5:1 이상, 컨트롤 경계·포커스 표시는 3:1 이상의 대비를 목표로 한다. 작은 스킬 그림도 클릭 영역은 최소 32 CSS px로 확보한다. 확대 시 긴 이름은 말줄임하고 선택하거나 포커스를 주면 전체 이름을 볼 수 있다.
- **알림 위치.** 입력 오류는 해당 입력 옆, 업무 오류는 해당 카드와 로그, 사용자 결정은 비서의 질문에 둔다. 다른 세션에서 답이 필요하면 세션 선택기에 대기 건수를 표시하고 사용자가 눌렀을 때 그 질문으로 이동한다. 새 로그나 잡담으로 현재 대화를 가리지 않는다.
- **저장·연결 실패.** 수락 전에는 성공 표시를 확정하지 않는다. 어떤 내용이 저장됐는지 불분명하면 같은 요청 ID로 상태를 확인한다. 같은 질문에 두 번 답하거나 중단·저장을 연타해도 첫 유효 변경만 반영한다. 네트워크가 끊겨도 로컬 기록 열람은 가능하고, 연결이 필요한 동작에 원인과 복구 수단을 붙인다.

**빈 화면과 대기 화면.** 세션에 첫 메시지가 없으면 빈 본문과 입력창, 로그에 사건이 없으면 ‘아직 기록된 활동이 없어요’, 담당자 기억이 비어 있으면 ‘아직 남긴 기억이 없어요’를 표시한다. 조회 중에는 결과 영역 안에만 로딩을 표시한다. 조회 실패는 그 위치에 원인과 다시 읽기를 두며 저장된 마지막 값이 있으면 마지막 확인 시각을 함께 보여준다. 재조회는 모델 실행을 시작하지 않는다.

## 8. 한 업무를 끝까지 따라가기

1. 사용자가 “빈 검색어도 처리해줘”를 보낸다. 비서가 협업으로 분류하면 ‘검색 개선’ 카드가 생기고 보내기가 ‘검색 개선 멈춤’으로 바뀐다. 시작한 세션, 업무, 지시 버전을 연결한다.
2. 플랜 담당이 요청에 맞는 위키 지침을 찾아 범위와 완료 조건을 기록하고 개발 담당에게 넘긴다. 캠프에서 두 사람이 만나며, 로그를 열면 같은 요청에 붙은 지적과 보완본이 보인다. 인계 상세에서 개발 담당이 받은 플랜과 완료 조건을 확인한다.
3. 개발 도중 사용자가 “공백만 있는 입력도 포함해줘”를 보낸다. 비서는 추가 지시를 그 업무에 연결한다. 이미 끝난 옛 버전 테스트는 남겨 두되 새 완료 조건에 대한 검증을 기다린다. 대화에는 사용자의 추가 지시가 한 번만 나타난다.
4. 테스트가 도는 동안 사용자가 멈춤을 누른다. 입력창과 카드에서 중단 요청을 즉시 확인하고 캠프는 실제 정지 통보 때 마법진을 끈다. 확인이 늦으면 로그에 마지막 확인 시점과 응답 대기 중인 실행을 표시한다. 파일·부분 결과·초안은 남는다.
5. 사용자가 ‘이어가기’를 누른다. 비서는 마지막 변경을 확인하고 필요한 테스트를 다시 맡긴다. 리뷰·코딩 스타일 확인·테스트가 현재 버전에 통과하면 비서가 결과를 보고한다. 보고에서 변경 파일과 검증 근거를 열 수 있고, 완료한 카드는 상단에서 사라진다.
6. 테스트 담당이 다음에도 쓸 실행 방법을 위키에 기록한다. 사용자는 메모리 탭에서 작성자·명령·출처를 읽는다. 다른 세션으로 이동해도 프로젝트 위키에는 같은 문서가 보인다.

## 9. 설계 인수 시나리오

아래는 구현 후 확인할 예상 결과다. 현재 단계에서는 요청부터 마지막 표시까지 흐름을 대조한다.

| 시작 상태 | 조작 | 통과 기준 |
|---|---|---|
| 새 프로젝트, 빈 대화 | 폴더 선택을 취소한 뒤 다시 선택하고 간단한 질문 전송 | 취소로 빈 등록이 생기지 않는다. 질문·답변 말풍선만 있고 아바타·화자 줄·업무 카드는 없다. |
| 한글 초안 작성 중 | 조합 확정 Enter, 줄바꿈, 전송, 곧바로 연속 클릭 | 질문이 한 번 접수된다. 같은 클릭 연속 입력이 막 생긴 멈춤 버튼을 작동시키지 않는다. |
| 검색 개선 실행 중 | 추가 지시를 쓰던 중 ‘검색 개선 멈춤’ 클릭 | 초안 보존 → 중단 중 → 실행 정지 확인 → 중단됨. 후속 테스트가 시작되지 않는다. |
| 업무 A·B 동시 실행 | A를 선택해 추가 지시 전송, 이어서 A 멈춤. B는 그 사이 완료 | 추가 지시·중단 모두 A에 한 번만 기록되고 B는 정상 완료 보고를 남긴다. |
| 비서가 질문에 답하는 동안 백그라운드 업무 진행 | ‘응답 멈춤’ 선택 | 부분 답변이 남고 백그라운드 업무의 담당자·카드·실행 상태가 유지된다. |
| 사용자가 지난 메시지를 읽는 중 | 다른 업무가 승인 요청. 질문으로 이동해 거절 | 읽던 위치와 포커스를 유지하다가 명시적으로 이동한다. 거절한 업무만 대안을 검토한다. |
| 알바가 작업 중 | 해고 후 모션 줄이기 전환, 나중에 같은 결과 수정 요청 | 퇴장 예정 → 인계 한 건 → 범례 제거. 후임과 예전 결과를 같은 업무에서 볼 수 있다. |
| 저장 여부 불명 상태에서 앱 재시작 | 로그를 연 뒤 사용자가 재개 | 열람으로 실행되지 않는다. 기존 변경을 확인하고 마지막 미완료 단계부터 진행한다. |
| 이전 세션에 활성 업무와 위키가 있음 | `/clear` 실행 후 위키 열기 | 새 대화는 비어 있고 원 세션의 작업이 이어진다. 새 세션에 같은 프로젝트의 위키가 보인다. |
| 두 사람이 같은 위키·워크플로우를 편집 | 먼저 저장한 뒤 오래된 초안 저장 | 먼저 저장한 내용과 작성 중 초안을 각각 확인할 수 있다. 옛 초안이 새 버전을 덮어쓰지 않는다. |
| 편집기에서 병렬 리뷰·테스트를 연결 | 노드 위치만 변경한 뒤 키보드로 저장하고 돌아오기 | 실행 순서와 원래 세션 초안이 유지된다. 현재 변경의 필수 검증이 모두 끝나야 완료된다. |
| 좁은 창·키보드·모션 줄이기 | 범례로 담당자 선택, 로그 조회, 대화로 복귀 | 애니메이션 없이 요청자와 상태를 읽는다. 대화 입력과 멈춤 버튼을 가로 스크롤 없이 사용할 수 있다. |
